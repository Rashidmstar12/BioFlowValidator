GEN-005 would produce the same response because the real file also uses

**Implication**: `scipy` must be listed as a required (not optional) dependency
and verified in the installation docs.

## Section 3: Fault Severity Gradient Analysis

Rules were tested across a range of injected fault magnitudes to characterise
decision boundaries.

### NRM-002 — Library Size Imbalance

| Injected ratio | Detected? |
|---|---|
| 1.5× | ❌ No |
| 2.0× | ❌ No |
| 3.0× | ❌ No |
| 5.0× | ❌ No |
| 8.0× | ❌ No |
| 9.0× | ❌ No |
| **10.0×** | ❌ No (at exact threshold) |
| **10.5×** | ✅ Yes |
| 15.0× | ✅ Yes |
| 50.0× | ✅ Yes |

**Known limitation**: 3–9× imbalances that can still bias DESeq2 size factors
are NOT detected.  DESeq2 vignettes recommend investigating even 5× imbalances.
The 10× threshold is conservative and should be documented.

### SMP-005 — Near-Identical Samples

| Injected Pearson r | Detected? |
|---|---|
| 0.985 | ❌ No |
| 0.990 | ❌ No |
| 0.993 | ❌ No |
| 0.995 | ❌ No |
| 0.997 | ❌ No |
| 0.998 | ❌ No |
| 0.999 | ❌ No |
| 0.9995 | ❌ No |
| **1.0000** | ✅ Yes |

**Observation**: In synthetic integer count data, the threshold of r ≥ 0.999
is only reached at r = 1.000 (exact duplicate) due to quantisation artefacts.
On real data with truly near-identical biological replicates or technical
duplicates, Pearson r routinely reaches 0.9990–0.9999 and the rule will fire.
Exact integer duplicates (r = 1.000) are always caught.

**Known limitation**: r = 0.990–0.998 near-duplicates (common in some
batch-correction failures) are missed.

### BIO-007 — Batch Confounding

| Cramér's V | Detected? | Severity |
|---|---|---|
| 0.00–0.65 | ❌ No | — |
| 0.70 | ❌ No | — |
| 0.75 | ❌ No | — |
| 0.80 | ❌ No | — |
| **0.90** | ✅ Yes | WARNING |
| **1.00** | ✅ Yes | ERROR |

**Observation**: The WARNING threshold is 0.7, but in a 2×2 contingency table
with small N the Cramér's V does not produce values in the 0.7–0.9 intermediate
range — it jumps from low values to ERROR.  On real data with more conditions
or more samples, the WARNING range (0.7 < V < 0.999) becomes accessible and
provides a useful intermediate signal.

**Known limitation**: Moderate confounding (V = 0.6–0.7) with small N (<6
per group) is not detected and generates no WARNING.

## Section 4: Dataset-Specific Caveats

### GSE52778 (human airway smooth muscle, Himes et al. 2014)

- **Suitable for**: main clean benchmark, paired design test (BIO-007), human
  Ensembl organism detection (GEN-005).
- **Classification**: main benchmark set.
- **Caveat**: This proxy uses the same gene ID pool as the existing `airway`
  proxy (they model the same real dataset).  On real GEO data, GSE52778 has
  ~33,469 genes vs. ~63,677 in the Bioconductor `airway` package because the
  GEO deposit does not include all zero-count genes.

### GSE60450 (mouse mammary gland, Law et al. 2014)

- **Suitable for**: testing Entrez ID namespace, 2-cell-type × 3-stage design,
  BIO-007 with biological condition/batch cross-classification.
- **Classification**: complexity/stress-test set (non-Ensembl gene IDs).
- **Caveat**: GEN-005 cannot detect organism from Entrez IDs — expected INFO
  result that should be documented in the paper.  BIO-005 (single-gene
  dominance) may fire on luminal cells at the lactating stage on real data
  where milk-protein genes can dominate.

### GSE107011 (human PBMC, Monaco et al. 2019)

- **Suitable for**: large multi-class design (7 cell types × 4 donors), donor
  batch confounding test, BIO-007 with many conditions.
- **Classification**: complexity/stress-test set.
- **Caveat**: With 7 conditions and 4 batches in a 7×4 contingency table, the
  avg expected cell count is 28/28 = 1.0, well below the Cochran 1954 threshold
  of 5. BIO-007 appends a small-sample caveat to any confounding result.
  On real data with 114 samples (29 cell types × 4 donors), the avg expected
  cell count = 114/116 ≈ 0.98 — even lower.  BIO-007 results on this dataset
  should be interpreted with this caveat.

**Notes on baseline capability**:

- **FastQC/MultiQC** operates on raw FASTQ reads, not count matrices.  It
  cannot inspect matrix orientation, gene IDs, sample labels, or normalization
  type.  The only partial coverage is library size (via total-reads report in
  MultiQC) and near-identical samples (via duplication metrics — indirect
  proxy only).

- **ENCODE checklist** (https://www.encodeproject.org/data-standards/rna-seq/)
  covers format, sample annotation, and replicate requirements.  It does not
  automate detection — a human reviewer must interpret the guidelines.

- **PCA + boxplot** detects structural outliers and batch separation visually
  but requires user interpretation.  It does not inspect gene IDs, encoding,
  or normalization type.

- **BioFlowValidator** produces deterministic, machine-readable results with
  quantitative evidence (Cramér's V, affected items, etc.) and covers all
  7 fault types plus 25 additional rules the baselines cannot express.

## Section 7: Honest Assessment for Publication

### What this benchmark demonstrates

1. **BioFlowValidator detects extreme, unambiguous faults reliably** (56/56
   real-faulty cases; 0 false positives on 8 clean datasets).

2. **Fault detection requires correct installation**: BIO-007 has a hard
   `scipy ≥ 1.11` dependency.  Missing scipy silently reduces batch-confounding
   recall to 0.000.

3. **Borderline cases are NOT tested** in the current benchmark.  All fault
   injection is at levels far above the rule decision boundaries (50× library
   size, exact duplicate samples, perfectly confounded batches).

4. **The benchmark does not distinguish between proxy and real data** —
   structural proxies are used throughout.  The fault detection is therefore
   testing the rule logic, not the biological signal of real RNA-seq data.
