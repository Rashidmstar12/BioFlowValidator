# BioFlowValidator — Rule Rationale Table

This table documents every validation rule in BioFlowValidator, including the
biological/statistical rationale, citation, and known caveats.  It is intended
for use as **Supplementary Table S1** in the manuscript.

Rules are listed in execution order (FMT → SMP → GEN → NRM → BIO).

---

## Format Rules (FMT)

| rule_id | rule_name | severity | threshold | biological / statistical rationale | primary citation | false-positive risk | false-negative risk | caveats |
|---|---|---|---|---|---|---|---|---|
| FMT-001 | EncodingRule | ERROR | Non-UTF-8 encoding detected | Non-UTF-8 characters in sample or gene names cause silent parse failures in downstream tools (pandas, R read.table, DESeq2). UTF-8 is the universal standard for plain-text genomics files. | [Strandberg et al., best-practices encoding; Unicode Standard §3] | Very low — most modern systems produce UTF-8. Rare FP with UTF-8-BOM (BOM is accepted as a variant). | Files with extended ASCII (Latin-1) will fail; no FN risk if encoding detection by chardet is reliable. | Chardet detection has ~95% accuracy; near-pure ASCII files may be misidentified. Windows-generated files with UTF-8-BOM are explicitly accepted. |
| FMT-002 | DelimiterRule | WARNING | Inconsistent delimiter | Mixed delimiters (e.g. some tabs, some commas) cause rows to parse with wrong column count, silently misassigning sample IDs. Consistently tab-separated (TSV) is the recommended format for genomics data (e.g. GEO submission guidelines). | [GEO Submission Guidelines, 2023] | None — rule only reports what delimiter was detected; does not fail unless inconsistency is found. | — | Fires as PASS for single-delimiter files; ambiguous files with mixed delimiters in different rows are the target. |
| FMT-003 | HeaderRule | ERROR | Sequential integer column names (0,1,2…) | Missing header rows cause all sample IDs to be assigned as integer indices, making sample-metadata matching (SMP-001) impossible. | [pandas read_csv documentation; R read.table defaults] | Non-sequential integer column names (Entrez IDs used as sample IDs) are specifically excluded from the heuristic to avoid FP. | Matrices with non-sequential numeric sample names would PASS even if header is missing. | Heuristic only: detects sequential 0-based or 1-based integer columns. Custom integer sample IDs could produce FP. |
| FMT-004 | DuplicateColumnRule | ERROR | Any duplicate column name | Duplicate sample column names cause pandas to silently renumber them (SampleA, SampleA.1), breaking SMP-001 matching. DESeq2 raises an error; edgeR silently includes both. | [DESeq2 user guide §2.1; edgeR user guide §1.4] | None — detecting exact duplicate strings is deterministic. | — | Applies only to count matrix columns; does not check metadata index for duplicates (that is SMP-003). |
| FMT-005 | NonNumericRule | ERROR | Any non-numeric or NA value | Non-numeric values in the count matrix (e.g. text annotations, NA, empty cells) cause DESeq2 to crash with an opaque error. | [DESeq2 vignette; HTSeq output format] | Files with legitimate NA annotations in specific columns might trigger this; however, count matrices should never contain NA. | — | Coercion via pd.to_numeric — complex expressions like "1,000" (locale-formatted numbers) are flagged as non-numeric. |
| FMT-006 | NegativeCountRule | ERROR | Any value < 0 | Negative read counts are biologically impossible and indicate corrupted or incorrectly normalised data. DESeq2 and edgeR assume non-negative integer counts; negative values cause numerical errors. | [DESeq2 vignette §1; Anders & Huber 2010, Genome Biology] | None — negative integer detection is deterministic. | — | Log-fold change values accidentally pasted into a count matrix would be caught correctly. |
| FMT-007 | WhitespaceNameRule | WARNING | Leading/trailing whitespace or special characters in sample/gene names | Whitespace in sample IDs causes SMP-001 matching failures (e.g. "SampleA" ≠ "SampleA "). R tools strip whitespace inconsistently. Special characters in gene IDs break formula parsers in limma/edgeR. | [R make.names() documentation; Bioconductor bioc-devel FAQ] | Legitimate special characters (hyphens in gene names like HLA-A, dots in ERCC-00002) should not trigger; only truly problematic characters (slashes, spaces in column names) are flagged. | — | Gene IDs with hyphens (common in HGNC) are excluded from the special-character check. |
| FMT-008 | MatrixOrientationRule | WARNING | n_cols > n_rows AND n_rows < 500 | A transposed matrix (samples × genes) makes every downstream rule fire as false positive — gene IDs are parsed as sample names and vice versa. This is a catastrophic, silent failure mode. | [bioinformatics community best practice; no single citation defines the 15,000-gene expectation — it reflects the human genome gene count] | Very low — any real RNA-seq matrix has thousands of gene rows. Targeted panels with < 500 genes would be a FP, but only if there are also > 500 samples, which is unusual. | A transposed matrix where n_rows > n_cols (i.e. more genes than samples even when transposed) would not be detected by this heuristic; only the most common case is flagged. | Threshold of 500 rows is empirical. Adjust via `_MAX_GENE_ROWS_FOR_TRANSPOSED` for targeted panel use. |

## Sample Rules (SMP)

| rule_id | rule_name | severity | threshold | biological / statistical rationale | primary citation | false-positive risk | false-negative risk | caveats |
|---|---|---|---|---|---|---|---|---|
| SMP-001 | SampleMatchRule | ERROR | Any sample ID in matrix not in metadata (or vice versa) | Sample ID mismatch means metadata annotations are silently misassigned to the wrong samples. This corrupts all DE analysis. Even a single mislabelled sample inflates false positives substantially (Schurch et al. 2016). | [Schurch et al. 2016, RNA, doi:10.1261/rna.053959.115] | None — set difference is exact. | — | Case-sensitive comparison. Leading/trailing whitespace (caught by FMT-007) can also cause apparent mismatches. |
| SMP-002 | SampleOrderRule | WARNING | Sample order in matrix ≠ metadata row order | Tools that rely on positional column matching (e.g. certain DESeq2 workflows) can silently assign wrong metadata if order differs. Not all tools enforce positional matching, so this is WARNING not ERROR. | [DESeq2 vignette §2.1 "important" note on sample order] | None — order comparison is deterministic. | — | Modern DESeq2 uses name matching not positional, so a strictly positional failure is now less common; WARNING is appropriate. |
| SMP-003 | DuplicateSampleRule | ERROR | Any duplicate sample ID in matrix or metadata | Duplicate sample IDs cause silent data duplication in DESeq2 model matrices, inflating degrees of freedom. edgeR produces incorrect dispersion estimates. | [DESeq2 user guide §2.1; Love et al. 2014, Genome Biology] | None — detecting exact duplicates is deterministic. | — | Checks both count matrix columns and metadata index independently. |
| SMP-004 | ReplicateCountRule | ERROR / WARNING | < 2 replicates per condition (ERROR); 2 replicates (WARNING, recommend ≥ 3) | Fewer than 2 biological replicates makes any dispersion estimate impossible; the DE test has 0 degrees of freedom. With exactly 2 replicates, statistical power is low and variance estimates are unreliable. | [Schurch et al. 2016, RNA: ≥ 6 replicates recommended; Robles et al. 2012, BMC Genomics; minimum 2 biological replicates per ENCODE standard] | None — replicate counting is deterministic. | Groups where n = 1 but the user intends pooled pseudo-replication are not detectable. | Condition column detection uses keyword matching (`condition`, `group`, `treatment`, etc.); non-standard column names cause SKIP. |
| SMP-005 | NearIdenticalSampleRule | WARNING | log1p-Pearson r ≥ 0.999 between any sample pair | Near-identical samples indicate either technical replicates mislabelled as biological replicates (inflating N) or de-duplicated data submitted twice. Either inflates statistical power illegitimately. | [Conesa et al. 2016, Genome Biology, doi:10.1186/s13059-016-0881-8; log1p transformation recommended for Pearson correlation in RNA-seq] | Biological replicates from highly homogeneous conditions (e.g. inbred mouse strain, clonal cell lines) can reach r = 0.995–0.998; the 0.999 threshold is conservative to avoid FP on such samples. | Technical duplicates at r = 0.990–0.998 are missed. The 0.999 threshold is conservative by design. | 500-sample guard prevents O(n²) hang on transposed matrices; see FMT-008. Log1p transformation is critical — raw Pearson is dominated by highly expressed outlier genes. |

## Gene Rules (GEN)

| rule_id | rule_name | severity | threshold | biological / statistical rationale | primary citation | false-positive risk | false-negative risk | caveats |
|---|---|---|---|---|---|---|---|---|
| GEN-001 | GeneIDFormatRule | ERROR | Mixed namespaces detected (> 1 namespace among Ensembl / Entrez / symbol) | Mixing Ensembl IDs with HGNC symbols makes gene ID → annotation mapping ambiguous: the same string can refer to different genes in different databases. DESeq2 results tables become uninterpretable. | [Ensembl documentation; HGNC nomenclature guidelines] | Very low — namespace classification is rule-based and unambiguous for standard IDs. | Minority contamination (< 10% of IDs from a second namespace) is not flagged; only cross-namespace majority conflict is an ERROR. | Checks first 2,000 gene IDs for performance. Ensembl-versioned IDs (ENSG….\d) are collapsed into the Ensembl namespace and handled by GEN-003. |
| GEN-002 | DuplicateGeneRule | ERROR | Any duplicate gene ID in count matrix index | Duplicate gene rows cause ambiguous feature counting (featureCounts can produce them for multi-isoform genes). DESeq2 crashes with an error on duplicate row names. | [featureCounts documentation; DESeq2 user guide] | None — detecting exact duplicate strings is deterministic. | — | Applies to the raw gene ID strings; version-stripped duplicates (ENSG001.1 and ENSG001.2 → same ENSG001) are NOT detected here; strip versions first (GEN-003). |
| GEN-003 | VersionSuffixRule | WARNING | Any Ensembl ID with version suffix (ENSG\d{11}\.\d+) | Version suffixes (e.g. ENSG00000141510.14) prevent matching against annotation databases (BioMart, AnnotationHub) that use un-versioned IDs. They also cause apparent duplicates after aggregation. | [Ensembl stable ID documentation; Bioconductor AnnotationHub vignette] | None — pattern matching is unambiguous. | IDs with very unusual versioning patterns not matching the regex would be missed. | Only human ENSG… versioned IDs are detected; multi-species versioned IDs follow the same pattern and are caught by the generic regex. |
| GEN-004 | NonBiologicalIDRule | WARNING | > 10% of first 500 gene IDs classified as "unknown" namespace | Gene IDs that match no known biological namespace (Ensembl, Entrez, or HGNC symbol) indicate the wrong column was used as the gene index, or a non-standard custom annotation was applied. | [GEO submission guidelines; INSDC feature table documentation] | Custom annotation IDs (e.g. Phytozome plant gene IDs, wormbase WBGene IDs) would trigger FP in non-standard organisms. | — | The 10% threshold is permissive; up to 10% unclassified IDs are tolerated to allow novel or non-standard gene models. |
| GEN-005 | OrganismDetectionRule | INFO | ≥ 80% of Ensembl IDs matching a single species prefix | Correctly detecting organism is critical for downstream rules BIO-005 (MT fraction threshold uses organism-specific gene prefix patterns) and BIO-006 (housekeeping Ensembl ID sets are organism-specific). | [Ensembl species prefix documentation; GRCh38/GRCm38 annotation releases] | Non-human/non-mouse organisms with Ensembl-format IDs will correctly SKIP downstream organism-specific checks. | Datasets with a mix of Entrez/symbol IDs will SKIP — organism-aware rules then use fallback heuristics. | Mixed-species contamination (> 10% IDs from a second species) is escalated to ERROR. This is the only rule that sets context.flags["organism"] for downstream rules. |

## Normalization Rules (NRM)

| rule_id | rule_name | severity | threshold | biological / statistical rationale | primary citation | false-positive risk | false-negative risk | caveats |
|---|---|---|---|---|---|---|---|---|
| NRM-001 | NonIntegerCountRule | ERROR | > 1% of values are non-integer | FPKM/TPM/CPM values are pre-normalised floating-point numbers. Submitting them to DESeq2 as raw counts causes it to estimate incorrect dispersion and size factors, producing biased DE results. | [Love et al. 2014, Genome Biology (DESeq2); Anders & Huber 2010, Genome Biology; Trapnell et al. 2012, Nature Protocols] | Very low. Some count pipelines (e.g. Salmon tximport rounded counts) can produce marginal floating-point rounding; the 1% threshold is permissive for such artefacts. | Rounded FPKM values (if always integer) would not be detected — the downstream NRM-005 (low-count sparsity) provides partial coverage. | 1% threshold is empirical. Any value with fractional part > machine epsilon is counted as non-integer. |
| NRM-002 | LibrarySizeRule | WARNING | Library size max/min ratio > 10× | Extreme library size imbalance introduces bias in TMM and RLE normalisation: size factors become inaccurate, inflating false positives for highly-expressed genes. Robinson & Oshlack 2010 show that highly unequal library sizes are a primary source of DE bias. | [Robinson & Oshlack 2010, Genome Biology, doi:10.1186/gb-2010-11-3-r25; Conesa et al. 2016, Genome Biology, doi:10.1186/s13059-016-0881-8] | Libraries from experiments with intentionally unequal depth (e.g. spike-in dilution series) would trigger FP. | 5× imbalance can still bias results; the 10× threshold is conservative. Investigators should inspect 3–10× imbalance manually. | The 10× threshold is widely used in community workflows but is not defined in a single authoritative paper. |
| NRM-003 | ZeroLibraryRule | ERROR | Total counts per sample < 1,000 | A library with < 1,000 total counts has suffered catastrophic failure (library preparation failure, barcode contamination, or empty well). Inclusion distorts size factors and leaves a sample with near-zero power. | [ENCODE RNA-seq standards 2011 (require ≥ 10M reads); analogous quality gate in Bioconductor RNA-seq workflows] | Targeted panels or spike-in libraries with < 1,000 total molecules could trigger FP. | Libraries with 1,000–100,000 counts may be under-sequenced but are not flagged; this is a catastrophic-failure sentinel only. | The ENCODE minimum is 10M reads (~30× higher); 1,000 counts is a bottom-of-range sentinel for complete library failures. |
| NRM-004 | AllZeroGeneRule | WARNING | Any gene with all-zero counts across all samples | All-zero genes carry no information, inflate the multiple-testing burden, and cause dispersion estimation issues in DESeq2 (estimated dispersion = Inf or NA). | [Love et al. 2014, Genome Biology (DESeq2 §1); Chen et al. 2016, F1000Research (edgeR quasi-likelihood pipeline, doi:10.12688/f1000research.9005.3)] | None — all-zero detection is deterministic. | — | Rule fires if any all-zero gene exists; the fraction of zero genes is reported but does not affect the FAIL/PASS call. |
| NRM-005 | LowCountDominanceRule | WARNING | > 50% of genes have median count < 1 across samples | When most genes have median count < 1, the entire library is under-sequenced or a wrong file was submitted (e.g. a filtered/normalised matrix). Dispersion estimates are unreliable on such sparse data. | [Robinson & Oshlack 2010 (CPM > 1 filter); Chen et al. 2016, F1000Research; Conesa et al. 2016] | Targeted panels, low-input RNA-seq, and single-cell pseudo-bulk from small clusters can legitimately have > 50% near-zero genes. | Libraries with exactly 50% low-count genes would PASS; the threshold is empirical. | 50% is an alert for extreme sparsity. Standard bulk RNA-seq from cell lines or tissue typically has < 30% all-zero genes after basic QC. |
| NRM-006 | DuplicateRowRule | WARNING | Any two non-zero gene rows with identical count profiles | Duplicate gene rows indicate data copy-paste errors during manual matrix assembly, or un-aggregated multi-isoform counting artefacts from featureCounts. They inflate library sizes and produce misleading DE statistics. | [featureCounts documentation; HTSeq user guide §3] | Very low — exact profile duplication in real RNA-seq data is exceedingly rare without a data error. | Genes with highly similar (but not identical) profiles are not detected. | Checks only non-zero rows (all-zero duplicates are handled by NRM-004 + NRM-006 is redundant for those). |

## Biology Rules (BIO)

| rule_id | rule_name | severity | threshold | biological / statistical rationale | primary citation | false-positive risk | false-negative risk | caveats |
|---|---|---|---|---|---|---|---|---|
| BIO-001 | SingleConditionRule | ERROR | < 2 distinct condition labels in metadata | Differential expression analysis by definition requires comparing at least two conditions. A single-condition matrix cannot produce a valid DE contrast. | [DESeq2 vignette §3; edgeR user guide §1] | None — condition counting is deterministic. GSE144269 is an intentional single-condition example. | — | Condition column detection uses keyword matching; non-standard column names SKIP the rule. |
| BIO-002 | ConditionLabelSanityRule | WARNING | All condition labels are purely numeric | Tools like DESeq2 treat purely numeric condition labels as a continuous covariate, not as factor levels. This silently changes the model from a group comparison to a regression. | [DESeq2 vignette §3 "colData factor levels"] | None — numeric detection is deterministic. | — | Mixed alphanumeric labels (e.g. "group1") are not affected; only fully-numeric strings trigger the warning. |
| BIO-003 | MetadataCardinalityRule | WARNING | Any metadata column with a unique value per sample | A column where every sample has a unique label is a sample identifier, not a condition variable. Passing it to DESeq2 as a condition factor gives each sample its own level, making the design matrix rank-deficient. | [DESeq2 vignette §2.1; experimental design best practices] | None — cardinality is exact. | — | Requires ≥ 3 samples to check (fewer samples could legitimately have unique values in valid experimental designs). |
| BIO-004 | HighCountGeneRule | WARNING | Any gene with max fraction > 50% of sample library | A single gene accounting for > 50% of a sample's reads indicates mapping artefacts (multi-mapping pile-up), annotation errors (merged gene models), or severe contamination. In normal bulk RNA-seq even the most highly expressed gene rarely exceeds 10–20%. | [Conesa et al. 2016, Genome Biology; no single citation defines the 50% threshold] | **HIGH FP RISK**: Haemoglobin genes in blood samples (HBA1, HBA2, HBB), albumin in liver, and β-globin in reticulocytes legitimately exceed 50%. Cardiac tissue also has physiologically high MT gene dominance. Always review in context of tissue type. | — | Checks per-sample max fraction, not average; a single outlier sample triggers the rule. |
| BIO-005 | MitochondrialFractionRule | WARNING | MT fraction per sample > 30% | High mitochondrial fraction in bulk RNA-seq indicates poor sample quality: degraded RNA (MT genes are enriched in cytoplasm and degraded more slowly than nuclear mRNAs), ruptured cells, or cytoplasmic RNA enrichment during RNA extraction. | [Conesa et al. 2016, Genome Biology (MT fraction as QC metric); Andrews et al. 2017, Bioinformatics (FastQC); Bioconductor RNA-seq workflow documentation] | **HIGH FP RISK**: Cardiac and skeletal muscle tissue have physiologically elevated MT expression (30–50% is normal in cardiomyocytes). The rule includes a caveat in the suggestion text. | Low MT fraction does not exclude poor quality; MT fraction is only one of several QC metrics. | Ilicic et al. 2016 (Nature Methods) provides MT QC guidance for *single-cell* RNA-seq, where thresholds are lower (5–20%). That paper should NOT be cited as authority for bulk RNA-seq thresholds. MT gene detection uses organism-aware prefix matching (human: MT-, mouse: mt-). |
| BIO-006 | HousekeepingGeneRule | WARNING | ≥ 80% of 10 reference housekeeping genes absent from matrix | Absence of well-known constitutively expressed genes (ACTB, GAPDH, B2M, etc.) is suspicious and may indicate a misformatted gene namespace, wrong reference genome, or extremely aggressive pre-filtering. | [Eisenberg & Levanon 2013, Trends in Genetics, doi:10.1016/j.tig.2013.05.010 — "Human housekeeping genes revisited"; human and mouse Ensembl IDs verified against Ensembl release 109] | Low for whole-transcriptome data. High for targeted panels (housekeeping genes deliberately excluded). | 20% tolerance (2 of 10 genes may be absent before FAIL) reduces sensitivity. | Supports HGNC symbol and Ensembl ID paths. Mouse orthologues from MGI. Entrez ID datasets SKIP (no lookup table). GEN-005 organism detection must precede this rule for correct Ensembl ID lookup. |
| BIO-007 | BatchConfoundingRule | ERROR / WARNING | Cramér's V ≥ 0.999 (ERROR, perfect confounding); V > 0.7 (WARNING, near-perfect) | Perfect confounding (V = 1) makes batch correction mathematically impossible: all variance in batch is also variance in condition. No existing pre-analysis tool detects this automatically at the count-matrix stage. | [Leek et al. 2010, Nature Reviews Genetics, doi:10.1038/nrg2825; Johnson et al. 2007, Biostatistics (ComBat); Cohen 1988, "Statistical Power Analysis" (effect size conventions for V > 0.7)] | None at V = 0.999. The V > 0.7 WARNING could fire on datasets with small N where Cramér's V overestimates association (Cochran 1954 small-sample issue, documented in rule). | V = 0.6–0.7 moderate confounding (the most common real-world case) does not trigger a FAIL, only passes silently. Users must check marginal confounding manually. | Requires a `batch` column (or similar) in metadata; SKIP if absent. Small-N guard: if average expected cell count < 5 in the contingency table, a caveat is appended to the output message (Cochran 1954, Biometrics). |
| BIO-008 | ERCCSpikeInRule | WARNING / ERROR | ERCC rows present (WARNING); any sample > 10% ERCC fraction (ERROR) | ERCC spike-in rows included in normalisation inflate library size estimates and distort DESeq2 size factors. edgeR silently includes ERCC rows in dispersion estimation. | [Lun et al. 2016, F1000Research, doi:10.12688/f1000research.9501.2; ERCC documentation (Thermo Fisher)] | None — ERCC-\d+ pattern matching is unambiguous. | User-renamed ERCC rows (e.g. "spikein_001") are not detected. | ERCC rows should be removed from the matrix before analysis; they can be saved separately for QC. The 10% fraction threshold for ERROR escalation is empirical. |

## Usage Notes for Reviewers

1. All thresholds marked **empirical** lack a single authoritative publication
   defining that exact value. This is common in bioinformatics QC; the
   justification is based on community consensus from workflow vignettes and
   best-practice surveys.

2. Rules with **HIGH FP RISK** require tissue-context awareness that the current
   tool does not have. Future work: allow users to declare tissue type and
   adjust thresholds accordingly.

3. Rules marked **SKIP** in expected behaviour are not failures — SKIP means
   "not applicable to this dataset type" and is the correct outcome.

4. Citations preceded by `doi:` are stable DOI-linked references. All other
   citations reference the primary publication venue (journal + year).
